# MathAgent 中文数学建模工作台

**MATLAB 实现对照与五人开工说明**

建议五个人用四周交付一条可以复算的建模流程。用户在 Windows 上打开中文数据，定义变量、目标和约束，在本机求解并导出结果。需要解释时，用户可以把选定的结果摘要发给自己配置的国产模型。算法给出数值，AI 辅助解释，用户始终能查到每个结论所依据的输入和计算结果。

**人员安排。** A 主写工程与任务服务并协调发布，B 主写中文界面与图表，C 主写数据导入与建模模板，D 主写国产模型接入，E 主写数值内核并负责内核测试。五个人分别测试自己的模块，接口由接收方交叉验收。

第 2–4 页给出本机实现和代码位置，第 5 页给出 MATLAB 实测基线，第 6–10 页每人一张开工单，第 11–13 页列出接口、联调顺序和发布条件。

### 首版交给谁用

以数学建模赛队为首批用户。组员甲用中文列名录入数据，组员乙检查模型和约束，组员丙在另一台电脑上打开工程，复算并引用图表。三个人交接的是一个可重开的工程、一份带单位的结果表和一张带图例的图。

### 用一道排产题验收整套软件

某车间生产甲、乙两种产品，按连续批量建模。每批利润分别为 3 万元、2 万元。每批都占 1 个机时，机时总量为 4；甲、乙的订单上限分别为 2 批和 3 批。令 x、y 为生产批量，目标为最大化 3x + 2y，约束为 x + y ≤ 4，0 ≤ x ≤ 2，0 ≤ y ≤ 3。

| 用户操作 | 团队共同核对的结果 |
| --- | --- |
| 导入数据并建立模型 | 中文字段与单位可见；用户能确认目标为最大化，并在运行前查看三项上限。 |
| 运行并查看结果 | 甲 2 批、乙 2 批，利润 10 万元。机时用满，乙的订单上限还余 1 批。甲的单位机时利润较高，手算可验证最优性。 |
| 改参数再运行 | 把机时改成 3，得到甲 2 批、乙 1 批、利润 8 万元。重开工程可复算；两次运行有各自的参数和结果。 |
| 选用 AI 解释 | 用户预览并发送摘要。解释关联到这次运行，导出时与数值结果分列。断网或未配密钥时，仍能完成本地求解与导出。 |

### 范围依据

技能明确约束 Windows 10/11 x64、Python 3.11.x、PySide6 6.7.x、QSS、双协议模型接入和 PyInstaller 6 目录式分发。本文建议首版仅承诺连续线性规划、中文 CSV、工程保存重开、结果 CSV 和 PNG 导出。曲线拟合作为第二个求解器候选；脚本语言兼容、框图仿真、完整工具箱和自动代写论文留待单独立项。

## 从中文数据表到求解器输入

**一份导入配置贯穿预览与读取。** 文本预览先检查选项类型，再用同一个 opts 调用 readtable，并加上行数上限；无数据有单独的错误。分隔文本选项把编码、分隔符、缺失处理和错误处理逐项传给解析器。由此划分工作：B 让用户编辑配置，C 实现一次解析，A 把确认后的配置与数据快照一起保存。预览成功只表示已读的那些行有效。参见 [S1]。

**建模描述要转换成数值问题。** Explorer 的 ProblemDef 识别最大化方向，向 prob2struct 指定目标求解器；转换后另存目标常数 f0。[S2] 对应到我们的接口，表单保存变量 ID、单位、约束方向，E 负责按固定 ID 顺序编译系数矩阵。用下式能抓住漏还原方向、漏加常数两类错误。

| 排产模型 | 编译给最小化后端的输入 | 恢复给用户的结果 |
| --- | --- | --- |
| 最大化 3x + 2y + 7 | c = (−3, −2)；A = [1, 1]，b = 4；变量上下界分别为 [0, 2]、[0, 3]。常数 7 独立保存。 | x = 2，y = 2。后端线性项为 −10，原式值为 17。E 用原式复算，A 保存原始方向与常数。 |
| 变量换序为乙、甲 | c、A 的列和上下界随 ID 一起换序。约束 ID 保持稳定。 | 表格按产品 ID 回填，仍是甲 2、乙 2。另用机时 3 的非对称结果检验错位。 |

**验证分三步。** linprog 先对齐向量、核对约束行列数，再检查非有限数与复数；矛盾的上下界可以在调用算法前返回不可行、空解、零次迭代。后续才构造问题结构、选择选项并运行算法。[S3] 用户可改的输入错误要能定位原单元格；数学不可行则在结果页解释。C 报导入与业务字段错误，E 报矩阵错误和数学状态，B 按来源展示。

## 数值内核的可见实现与分发边界

**线性规划的数值校验可以读到公式。** linprog 在需要诊断且有解时，按原始约束重算违反量。下层 calculateConstrViolations 分别算等式残差、线性约束上下界残差和变量上下界残差，与零一起取最大值；另行计算按行缩放的相对值。[S4] 上界 3、用量 2 对应余量 1、违反量 0。E 应分别输出这两个量，D 才不会把“尚余一批”解释成“违反约束一批”。

| 层次与可核查文件 | 安装目录显示的机制 | 我们据此作的决定 |
| --- | --- | --- |
| 算法分派 [S3、S5] | linprog 根据选项创建算法，再调用 run。双单纯形适配类以 .p 分发；内建注册清单把 Highs 和模型状态类映射到 libmwhighs_direct。 | E 采用白名单内 SciPy 的 HiGHS 双单纯形入口，独立做输入映射、状态翻译与回验；A 用自有依赖的 Windows wheel 打包。 |
| 矩阵与原生库 [S6] | 随附 C 示例先检查矩阵形状，再把维度、数据和步长传给 BLAS 的 dgemm；线性方程示例先复制输入，再调用 LAPACK 的 dgesv。 | E 明确二维矩阵形状、浮点类型和输入所有权。E 在发布包内真正做一次矩阵乘法和一次求解，暴露缺少原生库的问题。 |
| 稀疏数据 [S6] | fulltosparseIC 示例持有行下标和列指针，随非零数增长调整空间。 | E 在编译层保留变量列与约束行的映射，已有稀疏输入可走稀疏路径。B 只拿预览和结果摘要，避免为绘图复制整张矩阵。 |
| 第二类算法 [S7] | fit 同步筛选样本及权重。线性拟合分支用权重平方根缩放；无参数边界和约束点时做 QR 分解，检查系数唯一性及病态情况，计算残差平方和。 | 给拟合预留系数、残差、自由度和告警字段。首版只用拟合小题检查接口可扩展性，列入下一版时再开发。 |

**能查到的边界。** .m 和随附 C 示例可以逐行核对；清单和 DLL 可确认模块的存在及注册关系。双单纯形 .p 与 DLL 内部的枢轴选择、分解更新、线程策略，现有证据不足以确定。C 示例说明调用约定，其存在无法证明每个 MATLAB 表达式都经过该示例。

## 后台任务怎样变成用户看见的结果

在 Optimization Explorer 中，同一次运行有两类事实：求解器已经给出结果，以及后台执行单元已经结束。两者的通知可以经不同通道到达。将这条边界带进 MathAgent，可以防止用户取消后旧结果盖住新结果，也便于判断导出文件究竟属于哪次运行。

| 本机实现与证据 | 可观察的行为 | 交给 MathAgent 的接口 |
| --- | --- | --- |
| 执行器 [S8] | ExecutionState 单列 Starting、Running、Stopping；ParallelRunner 订阅数据队列和 Future 完成通知。队列再按 TaskID 区分迭代与完成消息。 | A 管 task_id、事件序号及唯一终态；E 只回传求解状态和数值；B 在收到取消请求后显示“正在停止”，待 A 确认终态才允许重跑。 |
| 保存与恢复 [S9] | Manager 保存模型、选项、目标和版本，再分别委托策略、任务、状态对象落盘。保存有强制路径和按时间间隔检查的路径。 | A 给每次运行保存输入、设置、结果及版本。写好新文件后再替换工程清单。C 在验收时让 A 注入替换前中断，重开应看到上一次完整提交。 |
| 结果展示 [S10] | ViewModel 订阅结果存在、停止原因、会话修改等事件；优化绘图回调在没有可画数据时返回，可按容差区分可行和不可行点。 | B 根据结构化状态启用图表、解释和导出；后端未给迭代数据时仅显示忙碌指示。CSV 和 PNG 都从相同 run_id 读取。 |
| AI 动作 [S11] | 表格解释在两个上下文注册，复用同一提示 ID、版本和回调；状态服务通过另一份清单注册。清单未公开其服务端协议。 | B 提供结果表旁的动作；A 提供已保存的运行记录；D 生成最小摘要、记录提示版本并处理供应商能力、协议与取消。国产模型双协议是本项目技能要求。 |

### 如何复算主基线
在 MATLAB 中令 c = [-3; -2]，分别取 b = 4 和 3。调用 [x,v,s,o] = linprog(c,[1 1],b,[],[],[0;0],[2;3])。读取 x、−v、s、o.constrviolation。正利润应从原模型解释。M09 用 optimproblem 的 maximize 目标加入常数 7，再调用 solve。
M10 用 writetable 写 12 行 CSV，detectImportOptions 后将 SelectedVariableNames 设为第二列，分别调用 preview 和 readtable。以上为参考软件实测；下列任务单列出的文件和验收项均为待开发交付物。

## E 数值内核开发与验证

E 的主要交付是可独立调用的线性规划内核。E 既写实现，也写内核单元测试和发布包科学栈冒烟。C 提供手算基线并从外部调用该内核交叉验证。A 负责进程生命周期；E 的求解入口可以在无窗口、无网络、无文件对话框条件下运行。参考 [S2–S6]。

| 工作项与时间 | 要写什么 | 接口消费者与签收标准 |
| --- | --- | --- |
| E1　第 1 周 | solvers/lp_compile.py 将 Problem 编译成 c、A_ub、b_ub、A_eq、b_eq、bounds，保留原始变量／约束 ID。最大化翻号，≥ 行乘 −1，等式单独存，常数留在原模型。 | 给 C 交排产编译快照；测试换列、显式负下界、空约束、非有限系数和维度错误。用机时 3 证明结果按 ID 回填。 |
| E2　第 1–2 周 | solvers/lp_backend.py 用 scipy.optimize.linprog 的 highs-ds 方法，显式传边界与时间上限。记录后端版本、原始状态与可用诊断，区分最优、不可行、无界、达限和数值失败。 | A 的 worker 只调用 solve(problem, options)。C 验 M01–M09；求解失败时目标值为可空字段，不把零当默认利润。 |
| E3　第 2–3 周 | solvers/lp_verify.py 在原始单位下复算目标、等式残差、逐条约束余量及违反量。分行采用明确容差；保留每条约束的 ID、单位、实际用量与上限。 | 给 B、D 交“乙剩余 1 批、违反量 0”的结构化样例。对测试桩故意返回的越界候选解，降为数值校验失败并标明出错约束。 |
| E4　第 3–4 周 | tests/solvers/ 覆盖编译、状态映射与独立回验；给 A 提供发布包内数值冒烟入口，比较稠密／稀疏解、版本、耗时、原生依赖加载。 | C 复核赛题目标、误差、迭代与耗时。A 在无开发环境的机器上运行整包，E 排查数值库故障；solvers 行覆盖率 ≥90%。 |

## 联调时以哪些接口为准

建议业务代码放在 mathagent/ 下，测试和 packaging/ 位于仓库根。core 提供无 Qt 的类型；app 经 services 调用 solvers、ai 和 viz。共享目录按下表的文件主责评审。服务可以试运行不同的模块；持久化只有 A 的工程服务一个写入口。

| 第几次交接 | 发起方 → 使用方 | 最小约定与失败处理 |
| --- | --- | --- |
| ① 读数据 | B → A 调度 → C 解析 | ImportSpec 含编码、分隔符、原列映射、缺失策略。Preview 返回列和源行号；正式导入输出 DatasetSnapshot。C 返回 FieldIssue(row, column, code)，B 就地提示。 |
| ② 建立问题 | C → E，同时给 B 预览 | Problem 含变量 ID／单位／上下界、原始目标方向／系数／常数、命名约束。C 定业务含义，A 维护契约文件，E 决定数值表示，保留映射。 |
| ③ 求解 | A → E → A | solve(Problem, SolveOptions) 返回 Solution，包含 solve_status、按 ID 的变量值、可空目标值、约束诊断、版本和运行指标。A 决定任务是否被取消，E 区分数学结果和后端错误。 |
| ④ 读结果 | A → B、D | RunRecord 绑定 run_id、快照、模型和结果。B 从同一记录生成表／图；D 经用户确认后取选定字段。迟到的解释按原 run_id 保存。 |
| ⑤ 签收 | 作者 → 接口接收人 | A 自测事件与恢复，B 自测 UI，C 自测导入与模板，D 自测双协议，E 自测数值内核。C 对 E 做独立数值回归，B 对 D 做消费测试；A 汇总。 |

**终态示例。** 求解器正常返回“不可行”意味着后台工作已完成且模型无解。界面可以查看诊断；目标值为空。“正在停止”期间收到旧结果时，按 A 已确认的任务状态作一次终态裁决。记录已取消的运行时不覆盖上次成功结果。

**国产适配约定。** D 用 httpx 直连用户显式配置的 HTTPS 地址。密钥取自环境变量、用户本机 .env 或 Windows 凭据管理器；界面仅显配置状态及末四位。连接、普通响应、流空闲超时分别为 10、120、300 秒。仅限流、网络及 5xx 最多重试两次，已有正文即停止重试。两套协议分别处理工具、停止序列、system 和流式事件。
