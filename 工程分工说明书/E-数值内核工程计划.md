# E 组连续线性规划内核工程计划

基线为 `main@c44a06f`，开发分支为 `feat/e1-lp-kernel`。首版面向 Windows x64、Python 3.11。A 的工作进程调用 `solve(problem, options)`，C 用带单位和稳定 ID 的模型交叉验收。

| 阶段 | 交付与验收 |
| --- | --- |
| E1 契约与编译 | 在 core/lp_types.py 定义数值 dataclass。验证 ID、形状、实数和有限性，保留原模型，按固定列序构造 HiGHS 所需的目标、约束和显式上下界。交付排产转换快照。 |
| E2 后端 | 通过 SciPy highs-ds 离线求解，默认时限 30 秒。返回数学状态、原码、消息、迭代数、版本与分阶段用时。A 负责进程和取消。 |
| E3 回验 | 在原单位下复算线性目标与常数、约束活动量、余量、等式残差及变量上下界违反量。用集中定义的绝对和相对容差逐项判定。只有验证通过的最优解提供目标值。 |
| E4 回归与冒烟 | 从公共入口执行 M01–M09、混合约束、非唯一解、错误候选解和不可变输入检查。为 A 提供无界面的原生矩阵乘法和稠密／稀疏 LP 自测。 |

## 性能与签收

- 稠密题为 256 行 × 256 列，稀疏题为 10,000 行 × 10,000 列、约 100,000 个非零元。用可解析的最优值验算，预热后计时五次，分别记录编译、求解和回验时间中位数、误差、最大违反量、迭代数和矩阵字节数。
- 稀疏输入保持稀疏，计算核使用 NumPy 和 SciPy 的白名单版本。求解入口同步返回结构化结果，无文件、网络或窗口依赖。
- Ruff、严格 mypy、pytest、密钥与依赖检查通过，求解器行覆盖率至少 90%，总行覆盖率至少 80%。C 的独立复核、A 的整包和干净 Windows 的运行证据分别记录。
- 实现按编译、求解与回验、回归与冒烟提交到本地功能分支。性能数据采用当前参考机实测。
